Projection notes

How R2 reads Claude Code

The local server tails the session transcript in ~/.claude/projects and extracts only the shape of each event: which tool was called, whether the result was an error, which subagent it came from. The session content never leaves your disk and is never sent to the page.

Module mapping

  • SNS video sensor → Read, Grep, Glob, LS
  • SCP scomp link arm → Bash and shell
  • MAN fine manipulator → Write, Edit, MultiEdit
  • TRX transceiver → WebSearch, WebFetch, MCP tools
  • VCK VicksVisc projector → Task and subagent lines
  • EXT fire extinguisher → tool_result with is_error
  • INT Intellex IV → model prose and token count
  • LOC locomotion → human turns and session activity

None of that is arbitrary: every module is a documented piece of R2-series equipment, assigned to the kind of work it resembles.

Session signals

The transcript carries far more than tool calls. These lines describe the run as a whole, so they map to the room rather than to a droid:

  • bench tiles → file-history-delta: one tile per file the session has edited, brighter the more often it is touched. The only thing here that persists.
  • bay ledger → cost-state: spend, lines added against lines removed, model time against tool time, and the bill per model.
  • floor rings → system/turn_duration: one ring per closed turn, sized by how long it took, fading over about a minute.
  • block stack → queue-operation: the real depth of the message queue, growing on enqueue and burning down on dequeue.
  • amber perimeter → permission-mode: lit while the session runs under bypassPermissions and is asking nobody.
  • beam colour → cache-read against fresh input tokens: cyan while the context is being reused cheaply, amber as it is paid for again.
  • sonar ping → model prose with no subagent behind it: rings leave from the antenna tips, the dome snaps round to face you and keeps scanning while the answer streams, and the callout reads TALKING. Prose arrives block by block, so each block holds the pose a few seconds.

File paths are the only part of this that touches your filesystem, and they are sent home-relative and never read: the path, not the contents.

The fleet

Each live subagent gets its own droid, and the series comes from the model behind the event. Canon: the R4 is identical to the R2 except its dome is conical rather than hemispherical, and the R5 has a shorter cone head and was the cut-price, unreliable unit. So opus runs as an R2, sonnet as an R4, haiku as an R5. The size difference encodes the model tier — that part is a reading aid, not a canonical dimension. Click any droid's tag for its readout — series, model, type, status, tools and tokens; the primary answers to its tag or to a click on its dome.

Workshop stations

A tool with a fixture is worked at that fixture: the droid drives over to the bench, the prop mounts on it and the bench lights up. One droid per station — the primary books first, then subagents in order, and whoever misses out keeps working from its own slot rather than standing inside someone else. When the work runs out a droid holds the spot where it finished instead of trekking back to the middle, swaying gently so it does not read as frozen.

When it asks you something

A droid waiting on an answer stops where it is, turns to face you and holds the question up: a plate carried in front of the dome on a cone of light, a question bar over a short list of choices, a caret walking the options. It is an unstable projection on purpose — scan lines crawl, the beat flickers and occasionally drops out, the whole plate drifts — because a steady rectangle reads as a label stuck on the screen rather than something the droid is projecting.

The panel carries no text. The wording of the question never leaves your disk, so what you see is that there is a question and roughly how many ways it can go, not what it says. Only the droid that asked stops; everything else in the bay carries on working, so a stalled unit stands out against the movement rather than freezing the room. Under prefers-reduced-motion the plate holds steady.

Replay and recording

Replay opens a transport over everything the page has received since you connected — the backlog the server replays on connect, plus whatever has arrived since. Drag the scrubber to land anywhere in that span, or let it play at 1× to 8×. Events that keep arriving while you are in the past are still recorded, so Live always returns to a current world rather than a stale one.

Scrubbing rebuilds rather than rewinds: the state here is cumulative (tokens, counters, which droids exist) and there is no way to un-apply an event, so the page resets and re-applies history up to the instant you picked. That is why it lands on a state that is actually correct instead of approximately correct.

Record captures the canvas to a video file and hands it to your browser when you stop. The container is whatever the browser supports — webm in most, mp4 on recent Safari. It records in real time, so recording a replay at 4× is the way to get a short video of a long session.

Moving around

  • drag to orbit, scroll to zoom, right-click a dome to glide in for a closer look
  • WASD or arrows to fly the camera, Q/E for height, Shift to speed up, R to re-centre on the droid
  • 1/2/3 or V for orbit, first person and third person. First rides the primary's eye; third gives you a holographic ball that bumps into the droids and the posts.

Nesting is inferred, not read

The transcript gives each subagent an agentId and an attributionAgent, but the latter is the agent type (general-purpose, fork) — there is no parent id anywhere in the format. So when a subagent calls Task and a new agent file appears shortly after, this page attaches the new droid to that one as a child and tethers it there. It is a heuristic based on timing, and it is labelled as such rather than presented as fact.

Colour channels

  • cyan — the projection itself
  • green — logic-display blip, a clean tool_result
  • red — logic-display blip, a failed one
  • amber — whole-body alarm, the extinguisher firing
  • chase — the dome lamp row running while the model thinks with no call open, or while the only open call is a Task handed to a subagent: green idle, blue waiting on you, amber waiting on the model, red on failure, with a fast flicker across the row on top and a slight sway of the whole droid

Sound

Off until you press Sound in the console — browsers need the gesture. Everything is synthesized live with WebAudio: chirps while it talks and when a subagent spawns, ticks as tools fire (throttled), a low buzz on errors, blips for human turns and connects, room tone underneath. No audio files, nothing licensed. Toggle choices persist in localStorage.
